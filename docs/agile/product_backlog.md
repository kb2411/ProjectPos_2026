
# Product Backlog

## Project Information

Project: ProjectPos_2026
System: Supermarket Point-of-Sale System
Development Method: Agile / Scrum-inspired
Developer: Individual Project

## Product Goal

Develop a small supermarket POS system that
supports sale processing and return handling.

## Product Backlog

| ID | User Story | Priority | Points | Iteration |
|---|---|---|---|---|
| US01 | As a cashier, I want to search for products so that I can find product information. | High | 2 | 1 |
| US02 | As a cashier, I want to add products to a cart so that I can record purchased items. | High | 3 | 1 |
| US03 | As a cashier, I want to see the total price so that I can inform the customer of the amount due. | High | 3 | 1 |
| US04 | As a cashier, I want to accept cash payments so that I can complete a sale and calculate change. | High | 5 | 2 |
| US05 | As a cashier, I want inventory to update after a sale so that stock records remain accurate. | High | 3 | 2 |
| US06 | As a cashier, I want to generate receipts so that customers can obtain proof of purchase. | High | 2 | 2 |
| US07 | As a cashier, I want transactions to be saved so that completed sales can be retrieved. | High | 3 | 2 |
| US08 | As a cashier, I want to search previous transactions so that I can verify return requests. | High | 3 | 3 |
| US09 | As a cashier, I want to process returned items so that customers can receive appropriate refunds. | High | 5 | 3 |
| US10 | As a cashier, I want returned stock to be restored so that inventory remains accurate. | High | 3 | 3 |

## Iteration Plan

Iteration 1:
- Product model
- Product lookup
- Shopping cart
- Total price calculation

Iteration 2:
- Cash payment
- Inventory deduction
- Receipt generation
- Transaction persistence

Iteration 3:
- Transaction lookup
- Return processing
- Inventory restoration
- Integration testing

## Progress Tracking

Progress will be recorded after each development
checkpoint using completed story points.

This is a compressed, Scrum-inspired educational
project. Calendar-based Sprint durations will not
be presented as actual elapsed development time.
